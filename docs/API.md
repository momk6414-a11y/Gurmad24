# GURMAD 24 - API reference (generated)

Generated by `npm run docs` from the live route table (98 endpoints).

**Conventions**
- Base path `/api`. JSON in, JSON out (CSV for `*.csv` exports).
- Authentication: httpOnly session cookie `g24s` set by `POST /api/auth/login`. No tokens in JavaScript.
- State-changing requests must be same-origin with `Content-Type: application/json`.
- Errors: `{ "error": "code", "fields": { "field": "reason" } }` with HTTP 400/401/402/403/404/409/413/415/429/501.
- Money is integer cents; commission rates are basis points (100 = 1%).
- All payments are **sandbox**; no real money moves. Emergency cases are **SIMULATION** only.

## Emergency demo: ambulance, police, fire (simulation)

All of this is SIMULATION. Nothing real is dispatched or contacted.

- `GET /api/config` now also returns `areas` (demo area presets with coordinates) and `responderTypes`.
- `POST /api/emergency/simulate` body: `category` (`general|transport|accident|maternal|other|fire|rescue|crime|disturbance`), optional `note`, and a location: either `areaId` (a preset), or `lat`, `lng`, optional `accuracy` plus `consent: true`. Coordinates are rounded to 4 decimals. Returns `case.code`, `case.responder` and a private `case.trackToken`.
- `GET /api/emergency/track/:code?token=...` live simulated status: status, history, unit position, station, ETA minutes. Wrong or missing token gives 404.
- Demo autopilot (public requests only): received, assigned (nearest unit of the right type), en route, arrived, help given, closed, computed from timestamps. Any operator or responder action stops it.
- Responder types are `ambulance`, `police`, `fire`. Responder accounts use the `provider_admin` role with an organisation of that type. Demo logins: `police@` and `fire@demo.gurmad24.test`.
- `GET /api/ops/cases?status=&responder=`, `GET /api/ops/providers?type=` support filtering.
